# AI Agent Lab：面试展示与简历素材

本页只使用已经实现、可以离线复现的内容。项目目前**没有真实模型评测数据**，因此不填写 Agent 成功率、模型成本或优化收益。

## 2 分钟展示路线

演示时打开[离线导览页](demo.html)。先看页面顶部，再依次点“浏览 20 个真实缺陷”和“查看执行轨迹”。

| 时间 | 页面操作 | 讲述重点 |
|---|---|---|
| 0:00–0:25 | 展示项目首页与状态卡片 | 项目解决什么问题；现在完成到哪一步 |

| 1:30–1:50 | 展示测试反馈和补丁 | 临时副本、公开测试、独立验收、补丁保存 |
| 1:50–2:00 | 回到状态说明 | 离线演示与真实模型评测的边界 |

### 可以照着说

> 这是我做的一个小型 Issue Fix Agent 实验项目。输入一个 Python 仓库和明确的 Issue，程序会先复制仓库、运行修复前测试，再通过受限的文件工具查找、修改代码和运行固定测试，最后保存执行轨迹、补丁和报告。
>
> 我目前整理了 10 个合成练习任务和 20 个来自四个开源项目的真实历史缺陷任务。真实任务都固定了上游提交，并离线验证了修复前测试失败、应用参考修复后公开测试和独立验收通过。这里我点开一个任务，你可以看到原始要求和参考代码变化。
>
> 这边的执行轨迹来自一个脚本化计算器演示：先读取 `calculator.py`，再精确替换错误的返回语句，最后运行测试。每一步都有参数和结果，最终补丁也可以检查。这个演示用预设响应驱动，没有调用付费模型；它证明工具链能工作，不证明模型能自主修复。真实模型成功率需要以后固定配置并跑完整评测集才能报告。

## 简历可用表述

建议把它放在“个人项目”，项目名可写 **AI Agent Lab｜Issue Fix Agent**。以下三条可以按版面选用：

- 基于 Python 实现面向小型仓库 Issue 的修复流程，提供文件检索、分段读取、精确文本编辑和固定测试工具；在临时仓库副本中执行并保存补丁与逐步轨迹。
- 构建 10 个合成任务和 20 个来自 tqdm、PySnooper、Tornado、youtube-dl 历史修复记录的真实缺陷任务；固定源码提交，验证修复前失败、应用参考修复后公开测试与独立验收通过。
- 实现路径限制、测试超时、修改文件数与编辑次数上限，以及运行结果分类和批量汇总；提供无需 API 费用的离线演示页面，便于审阅任务、工具调用和测试反馈。

**暂时不要写：**“Agent 修复成功率 X%”“比基线提升 X%”“平均成本 X 元”“在真实仓库上自动修复 20 个 Issue”。当前没有支持这些结论的真实模型运行结果。20 个真实任务是评测题目，不是 Agent 已解决的数量。

## 面试追问速答

**为什么需要独立验收，而不是只看公开测试？** 公开测试可能覆盖不全，也可能被针对性修改。项目阻止工具编辑测试文件，并在 Agent 临时仓库之外运行独立验收；只有两组测试都通过，才把任务标为成功。独立验收代码仍在公开仓库中，所以它不是对具有仓库外访问能力的模型保密。

**如何限制 Agent 的操作范围？** 模型只拿到预定义的文件和测试工具，不能自行选择 shell 命令。工作目录是临时副本，文件工具检查相对路径、符号链接、文件类型和大小；测试命令事先固定，运行时不继承 `OPENAI_API_KEY`。这是面向可信本地仓库的实验边界，不是通用的不可信代码沙箱。

**当前最重要的局限是什么？** 还没有真实模型端到端运行，所以无法报告 Agent 成功率、失败分布和成本。下一阶段应固定模型、提示词、任务集和最大步数后评测，并按轨迹分析失败，再做优化前后对比。

## 离线复现

在仓库根目录运行以下命令；均不使用 API：

```powershell
python -m unittest discover -s tests -v
python -m issue_agent.cli demo
python -m issue_agent.cli check --tasks real_tasks/tasks.json
python -m issue_agent.cli verify --tasks real_tasks/tasks.json --fixes real_tasks/checks/reference_fixes.json
python docs/build_demo.py --check
```

`demo` 产生的 `report.json`、`trace.json`、`changes.diff` 位于输出目录；导览页中的执行轨迹快照可用 `python docs/capture_demo.py` 刷新，再运行 `python docs/build_demo.py` 更新静态页面。
